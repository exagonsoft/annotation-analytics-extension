## Reproduce

```powershell
npm ci
npm run lint
npm test
npm run package
npm run test:e2e
npm audit
```

If Chromium is missing, install it with `npx playwright install chromium`. Integration tests own a temporary profile, local HTTP server and browser process; they close and remove only those test resources.

The first browser check loads the unmodified production manifest. Subsequent collection checks copy the bundle to a temporary directory and pregrant the local test origin plus the fixed LinkedIn origin used by a fully routed synthetic test. This avoids an unautomatable headless native permission dialog without changing application code or the production manifest. The local fixture issues an HttpOnly session cookie and requires it for task-list/detail responses. All LinkedIn-shaped test traffic is intercepted and fulfilled within the test; no real LinkedIn request is sent.

Browser tests capture actual DevTools response bodies, exercise the API UI, mappings and filtered metrics, open the annotation inspector, download CSV, save a snapshot, restart the browser with the same profile, and observe DOM mutations. Screenshot artifacts go to `artifacts` and are not shipped. The source of all fixture statistics is synthetic test data; the installed production extension starts empty.

The review test adds a local test-only module containing the original self-contained fetch/abort functions to that temporary extension copy. It invokes them through actual `chrome.scripting.executeScript` in the fixture tab's ISOLATED world, verifies the HttpOnly browser session is used, and tests cancellation arriving before fetch registration. Only the test invocation supplies the fixture origin; production transport remains fixed to LinkedIn and is separately exercised to refuse the wrong origin. No test bridge is included in `dist` or the ZIP.

The additional compiled-UI test does not call that bridge: Sources' actual button initializes the production collector and fixed-origin transport. The test routes synthetic LinkedIn-shaped responses and a synthetic HttpOnly session, confirms two distinct annotation IDs (not their task ID), observes start diagnostics while a response is still pending, verifies review metrics and selected refresh, and exports sanitized diagnostics. The development-build run also executes Test Annotation Detail Request once through that same collector with zero retries. These routed checks are not a substitute for real-server acceptance.

Passing fixture tests does not establish access to a real annotation platform. The confirmed LinkedIn detail route and response fields are implemented, but no real LinkedIn session request or production listing pagination was tested. Endpoint access, result semantics, total scope and host/session behavior remain **NOT VERIFIED**. Follow [the real-session acceptance procedure](REVIEW_REQUEST_DEBUGGING.md#real-authorized-session-acceptance-procedure).

The website-driven browser test uses the compiled production UI and actual DOM clicks, Chrome navigation and DevTools response ingestion, not a mocked capture event. Its synthetic website script adds a fixture-only marker to its own GET; the test asserts that marker to distinguish website-owned requests from extension fetches. It verifies SPA and full-document task-link clicks, an absent-link navigation, saved progress after reopening Review Analytics, two successfully merged reviews and an immediate pause on a third native HTTP 403. No real platform credentials or request headers are used. See [website-driven real-session validation](REVIEW_REQUEST_DEBUGGING.md#website-driven-real-session-validation) before treating real-account collection as verified.
